What you are looking at

A 100% procedural island — nothing is downloaded except the program itself. On startup, the C++ demo grows every tree from an L-system grammar, sculpts the terrain heightfield, seeds the sea and a cloud density field, and then runs its simulation loop against the cvcGL scene graph:

  • Forest — each tree is grown from the grammar, then all wood and all needles are merged into just two VTK actors; the wind re-poses every tree each frame and re-uploads the merged vertex buffers (updateVertices), which is what makes hundreds of swaying trees real-time.
  • Sea & clouds — two live volumes, GPU ray-cast under WebGL2. The sea's scalars travel as a wave and its transfer function tracks the sun glint; the cloud field drifts and morphs, and casts a soft shadow texture onto the terrain.
  • Materials — the terrain and bark use fragment-shader bump maps injected through VTK's shader-replacement hooks (value-noise height, normal perturbed by its surface gradient).
  • Shadows — vtkShadowMapPass with a strided baker, running under WebGL2's depth textures.
  • Camera & HUD — the built-in cvc::gl::CameraController (turntable orbit / Quake-style fly) and cvc::gl::FpsHud ('F'). Both are cvc::state objects: every setting lives in the scene's state tree (forest.viewers.main.camera.*, …viewers.main.hud.*) and is two-way bound — a script write moves the camera; a key press shows up in the tree.

How it runs in a browser

This is the desktop C++ program — src/cvcGL/examples/lsystem_forest.cpp in libcvc — cross-compiled with Emscripten. VTK 9.5's WebAssembly backend (vtkWebAssemblyOpenGLRenderWindow) renders OpenGL ES 3 into the canvas above, browser input reaches the same interactor the native window uses, and the demo's own while-loop yields to the browser each frame via Asyncify. The whole dependency closure — the trimmed cvc core, cvcGL, VTK, Boost, zstd — is statically linked into one .wasm by the cvcpkg wasm toolchain. This hosted build is single-threaded (GitHub Pages cannot serve the COOP/COEP headers threads need); a -pthread variant builds from the same tree.

Build steps, porting notes and the package recipe are on the examples index.
